## 1. 项目概述

### 1.1 项目背景

本系统面向宽带及配套物联网设备（CPE / 路由器、SIM 卡等）的 B2B / B2G 销售与运维场景。业务以门店、物业、企业客户为主，涉及多运营商（移动 / 联通 / 电信）、多设备供应商（鲲鹏、华为、中兴等）。

当前业务依赖 Excel 和人工流转，存在信息分散、工单状态不透明、设备与财务数据脱节等问题。本系统旨在建设 **Web 管理端 + 小程序** 协同平台，实现全链路数字化管理。

### 1.2 建设目标

| 序号 | 目标 | 说明 |
|------|------|------|
| 1 | 销售接单 | 销售人员创建安装工单，维护客户、地址、联系人、安装需求 |
| 2 | 派单流转 | 将工单派发给安装 / 运维工程师，跟踪安装进度与状态 |
| 3 | 客户全生命周期 | 公海池获客、私海跟进、联系人维护、外呼触达 |
| 4 | 设备资产管理 | 设备与 SIM 卡入库、出库、库存预警，与工单强关联 |
| 5 | 财务闭环 | 应收 / 已收 / 未收、回款核销、开票、合同到期提醒 |
| 6 | 数据贯通 | 通过 MAC、SIM 卡号、工单号、合同号实现全链路追溯 |

### 1.3 系统边界

**范围内：**

- Web 管理端全部功能模块
- 销售 / 安装人员微信小程序
- 与 OSS、微信开放平台、外呼平台（基础）对接

**范围外（本期不做）：**

- 运营商 BOSS 系统直连
- 等保合规认证
- 电话条 CTI 深度对接（可作为增值项）
- 短信通知（可选增值）

### 3.1 角色定义

| 角色 | 职责 | 使用端 |
|------|------|--------|
| 系统管理员 | 用户 / 角色 / 菜单 / 数据权限配置 | Web |
| 销售 | 客户管理、接单、跟进、日程、外呼 | Web + 小程序 |
| 运维 / 安装人员 | 接收派单、现场安装登记、设备回填 | Web + 小程序 |
| 仓储管理员 | 设备 / SIM 卡入库、出库、库存 | Web |
| 财务 | 回款核销、开票、对账单、付费提醒 | Web |

### 3.2 权限模型

采用 **菜单权限 + 操作权限 + 数据权限** 三层控制：

| 层级 | 控制粒度 | 示例 |
|------|---------|------|
| 菜单权限 | 可见菜单 | 销售不可见「用户管理」 |
| 操作权限 | 按钮级 | 销售可「新建工单」但不可「派工」 |
| 数据权限 | 数据范围 | 销售仅看自己的客户和工单 |

### 3.3 预置角色权限矩阵

| 功能 | 管理员 | 销售 | 运维 | 仓储 | 财务 |

| 公海池 / 公海客户 | ✅ | ✅ | ❌ | ❌ | ❌ |

## 4. 核心业务流程

### 4.1 工单主流程（接单 → 派单 → 安装 → 回款）

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 销售接单  │ →  │ 派工派单  │ →  │ 设备出库  │ →  │ 现场安装  │ →  │ 确认完成  │
│ 创建工单  │    │ 分配人员  │    │ 绑定设备  │    │ 登记信息  │    │ 触发合同  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                                      │
                                                                      ▼
                                                               ┌──────────┐
                                                               │ 财务回款  │
                                                               │ 核销开票  │
                                                               └──────────┘
```

### 4.2 工单状态流转

| 当前状态 | 触发动作 | 目标状态 | 操作角色 |
|---------|---------|---------|---------|
| 待派工 | 派工 | 已派工 | 管理员 / 调度 |
| 待派工 | 取消 | 已取消 | 销售 |
| 已派工 | 开始安装 | 安装中 | 安装人员 |
| 已派工 | 安装失败 | 失败 | 安装人员 |
| 安装中 | 提交安装登记 | 已安装 | 安装人员 |
| 已安装 | 确认完成 | 已完成 | 销售 / 管理员 |
| 失败 | 重新派工 | 已派工 | 管理员 / 调度 |

### 4.3 客户公海流程

```
公海池（未分配）
    │ 领取
    ▼
我的客户（私海）
    │ 跟进记录
    ├── 持续跟进 → 创建工单
    └── 退回（手动 / 策略触发 N 天未跟进）
            ▼
        公海池
```

### 4.4 财务回款流程

```
工单完成 → 生成应收账单 → 销售跟进回款
                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
                 录入回款   上传凭证   财务核销
                    │         │         │
                    └─────────┴─────────┘
                              ▼
                    更新回款状态 / 进度 / 开票
```

## 7. 数据模型与业务规则

### 7.1 核心实体关系

```
Customer（客户） 1──N Contact（联系人）
Customer 1──N FollowUp（跟进记录）
Customer 1──N WorkOrder（工单）
WorkOrder 1──N Dispatch（派工记录）
WorkOrder 1──1 Installation（安装登记）
WorkOrder 1──N StockOut（出库单）
StockOut N──1 StockIn（入库库存）
WorkOrder 1──N Billing（财务账单）
Billing 1──N Payment（回款记录）
WorkOrder 1──1 Contract（合同）
```

### 7.2 编号规则

| 类型 | 格式 | 示例 |
|------|------|------|
| 工单号 | GD-YYYYMMDD-NNN | GD-20261025-088 |
| 入库单号 | RK + YYYYMMDD + NNN | RK20261027001 |
| 出库单号 | CK + YYYYMMDD + NNN | CK20261027001 |
| 合同号 | {城市代码}{YYYYMMDD}{序号} | SH20261105001 |

### 7.3 关键业务规则

| 规则 | 说明 |
|------|------|
| 工单删除 | 仅「待派工」可删除 |
| 工单修改 | 仅「待派工」可修改 |
| 出库绑定 | 出库必须关联工单，自动扣库存 |
| 设备唯一 | 同一 IMEI / MAC 不可重复出库 |
| 合同生成 | 安装完成第 8 天自动生成 |
| 公海退回 | N 天未跟进自动退回（可配置） |
| 数据隔离 | 销售仅看自己的客户和工单 |
| 回款逾期 | 超过计划日且未收清 → 已逾期 |
